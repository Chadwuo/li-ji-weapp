# 礼记落地页重构设计规范

## 设计目标

本次重构保留现有“四幕式故事”的情绪基础，但将页面整体升级为更克制、更文雅的东方纸本礼簿叙事。页面不以功能清单为主，而以品牌短诗的方式建立记忆点：礼记是把人情往来、年月祝福与生活节点妥帖收好的小程序。

首屏必须明确呈现品牌口号：

> 每一份人情，都值得礼记。

可见文案保持克制、诗性和留白；SEO 元信息继续保留“人情记账、随礼、收礼、份子钱、家人共享、查询统计”等工具关键词，避免搜索表达过弱。

## 目标受众

主要面向泛年轻用户。他们未必已经强烈意识到“人情记账”的工具需求，但会被“把生活关系整理得更体面、更有秩序”的审美和情绪打动。

页面应先让用户记住礼记的气质，再通过清晰可见的小程序界面和仪式化 CTA 告诉用户：这不是单纯概念站，而是一个真实可用的产品。

## 核心方案

采用“纸本礼簿叙事，保留长滚动核心”的方案。页面像一本礼簿被慢慢打开：

1. **封面：礼记**
   首屏以重新生成的产品诗意合成主视觉承载品牌第一印象。画面包含礼簿、请柬、印章、纸张和清晰的小程序界面。主标题使用“每一份人情，都值得礼记。”，副文案承接“把来往的心意、年月里的祝福，妥帖收进一册。”

2. **起笔：从一张请柬开始**
   第二屏不直接列痛点，而以婚宴、满月、乔迁等人情场景进入。重点表达：席散之后，名字还留在纸上；日子久了，心意却容易散在记忆里。

3. **入册：请柬变成记录**
   保留并重构现有长滚动段落。滚动时，请柬上的姓名、事由、时间、礼金、备注等信息被拆成纸签或墨线标签，温柔地归入小程序中的时光轴记录。

4. **成册：岁月里的往来**
   原“关系网”章节弱化为“年份页”或“礼簿索引”。用 2024 婚礼、2025 满月、2026 乔迁、升学等人生节点表现时间沉淀，暗示前瞻能力“时光轴”，不做硬功能说明。

5. **翻开：开始你的礼记**
   结尾以半开的礼簿和二维码收束。CTA 更仪式化，例如“翻开礼簿”“把下一份心意收好”，避免普通下载页或强销售话术。

## 视觉语言

整体从当前偏玻璃、渐变和悬浮卡片的互联网产品感，转向东方纸本文雅感。

- 色彩以纸白、淡墨、朱红、旧金、灰绿为主。
- 大面积背景保持温润留白，不使用重渐变铺满页面。
- 朱红用于印章、口号强调和关键 CTA。
- 旧金仅用于细线、书脊、装订、请柬边框等仪式细节。
- 灰绿用于时间轴、辅助标识和低饱和产品界面点缀。
- 阴影要轻，层次来自纸张堆叠、边缘、细线和留白。
- 圆角收敛，避免过度柔和的玻璃拟态。
- 页面组件统一为纸张、页签、墨线、书脊、印章、签条、礼簿索引等视觉母题。

新增主视觉资产应是“产品诗意合成”：礼簿、请柬和理想化小程序界面处于同一个纸本场景中。小程序界面要清晰可见，用户一眼能知道礼记是真实工具，但整体主角仍是礼簿和纸本场景。

## 文案方向

文案大幅重写，减少功能词和解释性句子，使用短句、场景和留白。

首屏：

- 主标题：每一份人情，都值得礼记。
- 副文案方向：把来往的心意、年月里的祝福，妥帖收进一册。

起笔：

- 方向：席散之后，名字还留在纸上；日子久了，心意却容易散在记忆里。

入册：

- 方向：取下姓名、日子与礼金，轻轻归入同一条时间。

成册：

- 方向：一年一年翻过去，婚礼、满月、乔迁、升学，都有了可回望的位置。

CTA：

- 方向：翻开礼簿，把下一份心意收好。

## 核心交互

“入册”是整页最重要的长滚动记忆点。桌面端分为四个状态：

1. **见礼**
   请柬和半开的礼簿/手机界面同时出现。请柬上的姓名、事由、日期、金额仍属于纸面。

2. **取字**
   字段被拆成几枚签条或墨线标签：姓名、事由、时间、礼金、备注。动画应像从纸面上轻轻取下信息，而不是冰冷的数据抽取。

3. **入册**
   签条进入手机里的时光轴，形成一条记录。例如“二零二六 · 新婚之喜 · 吴家”。金额和备注出现，但不抢主角。

4. **回望**
   手机界面中的记录与前后年份连起来，形成婚礼、满月、乔迁、升学等生活节点。这里暗示“时光轴”前瞻能力，不把它写成硬功能卖点。

技术上继续使用原生 JavaScript 控制状态，例如 `IntersectionObserver`、滚动进度、`data-step` 或 CSS 变量。不引入动画库。

## 移动端策略

桌面视觉优先，移动端保证好读、好看、不卡。

- 桌面端保留完整诗意长滚动。
- 移动端不硬撑长距离 sticky 滚动，可改为静态分段或轻过渡。
- 移动端仍保留“请柬 → 签条 → 时光轴”的理解链路。
- 手机端首屏要先看到口号和主视觉重点，避免二维码或装饰元素挤占阅读。
- 所有中文长句必须在小屏自然换行，不得挤压按钮或重叠视觉组件。
- 减少移动端大面积模糊和持续动画，保证微信内打开体验顺滑。

## 技术边界

保持 `landing/` 当前纯静态结构，不引入 Vue、Vite、构建工具或第三方动画库。

需要改动的文件：

- `index.html`：重排页面结构，重写可见文案，保留 SEO 元信息、二维码、备案和统计脚本。
- `styles.css`：重构为新的纸本视觉系统，包括色彩变量、排版、主视觉、礼簿组件、长滚动和移动端适配。
- `script.js`：整理入场显现、滚动状态、桌面层次动效；按新结构决定是否加入导航高亮。
- `assets/`：保留 `logo.webp` 和 `code.jpg`；`banner.jpg` 可不再作为首屏核心；新增一张或多张主视觉资产。
- `DESIGN_SPEC.md`：作为落地页自己的正式设计规范维护。

## 验证要求

实现后需要验证：

- 桌面端首屏是否明确呈现“每一份人情，都值得礼记。”
- 新主视觉是否能同时表达礼簿、请柬、小程序界面和纸本气质。
- 长滚动四个状态是否顺畅、可理解、不过度炫技。
- 移动端是否好读、不卡、无文字溢出和元素重叠。
- 二维码、备案链接、统计脚本仍可用。
- 中文编码正确，页面源码和浏览器显示不乱码。
- 在 `prefers-reduced-motion: reduce` 下动画可被显著削弱。
