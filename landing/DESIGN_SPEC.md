# 礼记落地页重构设计规范

## 新方向

上一版纸本礼簿页面视觉冲击不足，组件感明显。新版改为 **Apple-style 产品变形落地页**：浅色高级背景、巨大 iOS 风手机界面、GSAP + ScrollTrigger pinned scroll、多层 UI 剖面，以及从请柬入账到时光轴形成的连续产品镜头。

首屏口号保持：

> 每一份人情，都值得礼记。

## 核心体验

页面主体验是一个 6-8 屏长度的连续滚动镜头：

1. **开场：请柬纸本场景**
   首屏保留少量东方纸本情绪，作为故事起点。请柬、纸张和印章只做气质点缀，不再主导整页。

2. **拆解：请柬信息浮出**
   滚动进入 pinned 区，请柬放大，姓名、日期、金额、事由从纸面分离成悬浮信息层。

3. **登场：巨大 iOS 手机界面**
   手机成为主角。界面采用 iOS 原生高级感：白色层级、圆角玻璃、细分割、柔和阴影、克制颜色。

4. **入账：信息飞入手机**
   请柬字段沿路径飞入手机，生成“请柬入账”记录卡。

5. **剖面：UI 层级浮出**
   记录卡、金额标签、时光轴、年份节点从屏幕中分层浮出，形成空间纵深，再随滚动归位。

6. **成册：时光轴形成**
   二零二四、二零二五、二零二六等年份节点依次铺开，婚礼、满月、乔迁成为可回望的位置。

7. **收束：回到纸本礼簿**
   强产品镜头结束后回到安静礼簿。二维码像夹在书页中的笺纸，完成 CTA：“翻开礼簿，把下一份心意收好。”

## 视觉要求

- 保持浅色高级，不使用深色电影感背景。
- 手机界面是主角，纸本元素只服务开场和收束。
- UI 必须精致，避免粗糙卡片堆叠。
- 滚动动效必须连续，不再使用突兀的几段 `data-step` 状态切换。
- 桌面端优先完成强视觉，移动端保留顺滑阅读和核心层级，但可简化动画。
- 不再依赖生成位图主视觉；核心产品镜头用 HTML/CSS 绘制，便于 GSAP 控制。

## 技术要求

- 继续保持 `landing/` 静态页结构。
- 使用本地 `landing/vendor/` 中的 GSAP 和 ScrollTrigger，避免外部网络加载波动影响核心动效。
- 原生 JS 负责初始化 GSAP、导航高亮、入场显现和降级体验。
- 如果 GSAP 加载失败，页面必须仍然可阅读，只是失去高级滚动动效。
- `prefers-reduced-motion: reduce` 下禁用复杂滚动动画。

## 验证要求

- 静态验证脚本必须检查 GSAP 依赖、pinned scroll 脚本、巨大手机 UI、UI 分层、礼簿收束和移动端策略。
- 浏览器验证必须覆盖桌面首屏、pinned scroll 中段、时光轴剖面、CTA、移动端首屏和移动端 CTA。
- 控制台不得出现页面脚本错误。
